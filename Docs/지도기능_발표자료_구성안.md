### 3. 첫 번째 어려움: React Native에서 지도 구현 (1.5분)

#### 문제 상황
- **문제**: React Native에는 네이티브 Kakao Map SDK가 없음
- **시도**: react-native-kakao-maps 같은 라이브러리 탐색 → 미지원 또는 불안정
- **결과**: WebView를 통한 하이브리드 방식 선택

#### 해결 과정
1. **WebView 기반 지도 구현**
   - HTML + Kakao Maps JavaScript API
   - React Native WebView 컴포넌트 활용
   - JavaScript ↔ React Native 통신 (postMessage)

2. **발생한 문제들**
   - WebView 로딩 지연
   - 스크립트 로드 타이밍 이슈
   - 좌표 데이터 동기화 문제

3. **해결 방법**
   ```typescript
   // 재시도 로직 구현
   var retryCount = 0;
   var maxRetries = 20;
   function initMap() {
     if (typeof kakao === 'undefined' || !kakao.maps) {
       if (retryCount <= maxRetries) {
         setTimeout(initMap, 300);
       }
     }
   }
   ```

**발표 포인트:**
- "네이티브 SDK가 없어서 WebView를 선택했지만, 이것이 새로운 도전의 시작이었습니다"

### 4. 두 번째 어려움: GPS 위치 기반 구현의 어려움 - 속도 저하와 GeoLocation 오류 ⭐ 핵심 (4분)

#### 초기 계획: GPS 위치 기반 구현
```typescript
// 초기 구현 계획
const { coords: gpsCoords, error } = useCurrentPosition();
const searchCoords = gpsCoords; // GPS 위치 사용
```

#### 발생한 문제들

**문제 1: 위치 권한 처리의 복잡성**
```typescript
// Android 권한 요청
const granted = await PermissionsAndroid.request(
  PermissionsAndroid.PERMISSIONS.ACCESS_FINE_LOCATION,
  {
    title: '위치 권한',
    message: '카페 찾기 기능을 위해 위치 권한이 필요합니다.',
    // ...
  }
);

if (granted !== PermissionsAndroid.RESULTS.GRANTED) {
  // 권한 거부 시 처리
  setError('위치 권한이 필요합니다...');
  return; // ❌ 지도 기능 사용 불가
}
```

**발생한 이슈:**
- 사용자가 권한을 거부하면 지도 기능 자체를 사용할 수 없음
- 권한 요청 다이얼로그가 사용자 경험을 방해
- iOS와 Android의 권한 처리 방식이 다름
- 권한 거부 후 재요청이 복잡함

**문제 2: GeoLocation 속도 저하 및 오류 발생 ⭐ 핵심**

```typescript
Geolocation.watchPosition(
  pos => setCoords({ lat: pos.coords.latitude, lng: pos.coords.longitude }),
  err => setError(`위치를 가져오는데 실패했습니다: ${err.message}`),
  {
    enableHighAccuracy: true,
    timeout: 15000,        // 15초 타임아웃
    maximumAge: 10000,      // 10초 이내 캐시된 위치만 사용
  }
);
```

**속도 문제:**
- ❌ **위치 획득까지 5-15초 소요**: 사용자가 지도를 보기까지 긴 대기 시간
- ❌ **실내/지하에서 더 느림**: GPS 신호가 약한 환경에서는 20초 이상 걸리기도 함
- ❌ **앱 시작 속도 저하**: 지도 화면 진입 시마다 위치 획득 대기 필요
- ❌ **사용자 이탈 위험**: 로딩 시간이 길어질수록 사용자가 앱을 떠날 가능성 증가

**GeoLocation 오류 발생:**
```typescript
// 실제 발생한 오류들
err => setError(`위치를 가져오는데 실패했습니다: ${err.message}`)
```

**발생한 오류 유형:**
1. **타임아웃 오류 (Timeout Error)**
   - 15초 내 위치를 가져오지 못하면 타임아웃 발생
   - 실내나 지하에서 자주 발생
   - 에러 메시지: "Location request timed out"

2. **권한 오류 (Permission Denied)**
   - 사용자가 권한을 거부했거나 시스템에서 차단
   - 에러 메시지: "User denied the request for Geolocation"

3. **위치 사용 불가 오류 (Position Unavailable)**
   - GPS가 비활성화되어 있거나 하드웨어 문제
   - 에러 메시지: "Position unavailable"

4. **네트워크 오류**
   - 위치 서비스에 접근할 수 없을 때
   - 에러 메시지: "Network error"

**오류 발생 시나리오:**
- 사용자가 앱을 열면 → GeoLocation 호출 → 5-15초 대기 → 오류 발생 → 에러 화면 표시
- 이 과정에서 사용자는 아무것도 할 수 없음
- 오류 발생 빈도가 높아 사용자 경험이 크게 저하됨

**속도 및 오류로 인한 문제:**
- 위치 정확도가 낮을 수 있음 (수십 미터 오차)
- 실내나 지하에서는 GPS 신호가 약함
- **앱 반응 속도가 현저히 느려짐** ⭐
- **오류 발생 시 기능 자체를 사용할 수 없음** ⭐

3. ✅ **오류 제거**: GeoLocation 오류와 무관하게 안정적으로 동작 ⭐
4. ✅ **안정적인 UX**: 로딩 시간 없이 즉시 기능 사용 가능
5. ✅ **에러 처리 불필요**: GPS 실패와 무관하게 동작
6. ✅ **개발 편의성**: 테스트와 디버깅이 쉬움
7. ✅ **배터리 효율**: GPS 사용 안 함

### 5. 세 번째 어려움: 사용자 기반 부하 문제 (2분)

#### 문제 상황
- **증상**: 
  - 지도 중심을 드래그할 때마다 API 호출 발생
  - 여러 사용자가 동시에 사용 시 서버 부하 증가
  - Kakao API 호출 제한에 걸릴 위험

- **원인 분석**:
  ```typescript
  // 문제가 있던 코드 (초기 버전)
  kakao.maps.event.addListener(map, 'center_changed', function() {
    // 지도 중심이 조금만 바뀌어도 즉시 API 호출
    fetchCafes(center.getLat(), center.getLng());
  });
  ```
  - 지도 드래그 시 `center_changed` 이벤트가 초당 수십 번 발생
  - 사용자가 지도를 조금만 움직여도 API 호출 폭증

#### 해결 과정

**디바운싱(Debouncing) 적용**
```typescript
// 해결: 디바운스 적용
const handleCenterChanged = (coords: { lat: number; lng: number }) => {
  if (debounceTimerRef.current) {
    clearTimeout(debounceTimerRef.current);
  }
  
  // 500ms 후에만 위치 업데이트
  debounceTimerRef.current = setTimeout(() => {
    setMapCenter(coords);
  }, 500);
};
```

**효과:**
- API 호출 횟수: 초당 10-20회 → 2초에 1회로 감소
- 서버 부하 90% 이상 감소

**발표 포인트:**
- "하드코딩으로 전환했지만, 지도 드래그 시 API 호출 문제는 여전히 있었습니다"
- "디바운싱을 통해 불필요한 호출을 90% 이상 줄였습니다"

### 8. 마무리: 교훈 및 배운 점 (1분)

**핵심 교훈:**
1. **속도와 안정성이 최우선**
   - GeoLocation의 5-15초 대기 시간은 사용자 경험을 크게 해침
   - 오류 발생 시 기능 자체를 사용할 수 없게 됨
   - **빠르고 안정적인 기능이 완벽한 기능보다 중요** ⭐

2. **오류 처리보다 오류 예방**
   - GeoLocation 오류를 처리하는 것보다 오류가 발생하지 않도록 설계
   - 하드코딩으로 전환하여 오류 발생 가능성 자체를 제거

3. **사용자 경험 우선**
   - 권한 요청, 긴 로딩 시간, 오류 화면은 사용자 경험을 해침
   - 즉시 사용 가능하고 안정적인 기능이 더 중요

4. **실용적인 선택의 가치**
   - 기술적으로 완벽한 것보다 **빠르고 안정적인 것**이 우선
   - 필요시 나중에 개선할 수 있음

5. **실제 사용 시나리오 고려**
   - 개발 환경과 실제 사용 환경의 차이

- Q: "왜 GPS 위치를 사용하지 않고 하드코딩했나요?"
  A: "GPS 위치 기반으로 구현을 시도했지만, **GeoLocation에서 위치를 가져오는데 5-15초가 걸려 속도가 너무 느렸고, 타임아웃 오류, 권한 오류 등 다양한 오류가 자주 발생**했습니다. 이로 인해 사용자 경험이 크게 저하되었고, 하드코딩된 기본 위치로 전환하여 **즉시 지도를 표시하고 오류 발생 가능성을 제거**했습니다. 사용자는 지도를 드래그해서 원하는 위치를 탐색할 수 있어 더 실용적이라고 판단했습니다."

- Q: "나중에 GPS 기능을 추가할 계획이 있나요?"
  A: "네, 향후 개선 계획으로 GPS 위치를 선택적으로 사용할 수 있는 옵션을 제공하는 것을 고려하고 있습니다. 하지만 현재는 사용자가 지도를 드래그해서 원하는 위치를 탐색할 수 있어 충분히 유용한 기능입니다."

- Q: "하드코딩된 위치가 서울 중심인데, 다른 지역 사용자는 어떻게 하나요?"
  A: "사용자가 지도를 드래그해서 원하는 위치로 이동할 수 있습니다. 지도 중심을 변경하면 해당 위치 기준으로 주변 카페를 검색하므로, 서울이 아닌 다른 지역도 문제없이 사용할 수 있습니다."

- Q: "왜 네이티브 SDK를 사용하지 않았나요?"
  A: "React Native용 Kakao Map SDK가 공식적으로 제공되지 않아 WebView 방식을 선택했습니다."

- Q: "디바운싱 시간(500ms)을 어떻게 결정했나요?"
  A: "사용자 경험과 성능의 균형을 고려하여, 지도 드래그가 끝난 후 적절한 시간을 실험을 통해 결정했습니다."

## 📝 발표 스크립트 예시 (핵심 부분)

### GPS 위치 기반에서 하드코딩으로 전환한 이유 설명 부분

> "지도 기능을 개발할 때, 처음에는 **GPS 위치 기반**으로 구현하려고 했습니다. 사용자의 현재 위치를 가져와서 주변 카페를 보여주는 것이 가장 직관적이라고 생각했기 때문입니다.
> 
> 하지만 실제로 구현하면서 **심각한 속도 문제와 오류 문제**를 겪게 되었습니다.
> 
> **가장 큰 문제는 속도였습니다.** GeoLocation을 사용해서 위치를 가져오는데 **5-15초가 걸렸습니다**. 실내나 지하에서는 20초 이상 걸리기도 했습니다. 사용자가 앱을 열 때마다 이렇게 긴 시간을 기다려야 했고, 앱의 반응 속도가 현저히 느려졌습니다.
> 
> **두 번째 문제는 GeoLocation에서 발생하는 오류**였습니다. 타임아웃 오류, 권한 오류, 위치 사용 불가 오류 등이 자주 발생했습니다. 오류가 발생하면 지도 기능 자체를 사용할 수 없게 되었고, 사용자는 에러 메시지만 보게 되었습니다.
> 
> 이렇게 **속도가 느리고 오류가 자주 발생**하니, 사용자 경험이 크게 저하되었습니다. 사용자가 앱을 열 때마다 긴 대기 시간과 오류 가능성에 직면하게 되었습니다.
> 
> 그래서 **하드코딩된 기본 위치(서울 중심)로 전환**하기로 결정했습니다. 이렇게 하면 즉시 지도를 표시할 수 있어 **속도 문제가 해결**되고, GeoLocation을 사용하지 않아 **오류 발생 가능성도 제거**됩니다. 사용자는 지도를 드래그해서 원하는 위치를 자유롭게 탐색할 수 있습니다.
> 
> 완벽한 GPS 위치 기반 기능보다, **빠르고 안정적인 기능**이 더 중요하다는 것을 배웠습니다."
